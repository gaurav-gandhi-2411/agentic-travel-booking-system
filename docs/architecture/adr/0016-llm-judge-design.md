# ADR-0016 — LLM-Judge Design for Coherence Scoring

**Status:** Accepted  
**Date:** 2026-05-17  
**Deciders:** GG  
**Supersedes:** —  
**References:** ADR-0010 (eval harness), ADR-0015 (optimizer eval design)

---

## Context

Phase 2C.1 adds a coherence dimension to the optimizer eval. Label correctness
(ADR-0015) is deterministic: the scorer computes the expected Pareto labels
from math and compares. Coherence is not deterministic: it measures whether the
archetype explanation generated by the OptimizerAgent is logical, specific to the
actual flight shown, and well-framed for the labelled archetype.

We need an automated coherence judge that is:
1. Free (or near-free) to run in nightly CI
2. Stable enough to detect regressions (low variance across runs)
3. Cross-family from the models being evaluated (to reduce within-family bias)
4. Documentably defensible to external buyers reviewing the eval methodology

---

## Decision

### Judge pattern: Pattern 3 — Single judge with structured rubric

**Considered:**
- **Pattern 1 — Human review only.** Too slow, doesn't scale to CI.
- **Pattern 2 — Pairwise comparison (LLM picks A or B).** Requires a reference
  explanation, which we don't have. Also suffers from position bias and doesn't
  produce an absolute score useful for threshold-gating.
- **Pattern 3 — Single judge with structured 1-5 rubric.** Produces an absolute
  score. Bias is documented and mitigated. Variance managed with median-of-3.
- **Pattern 4 — Multi-judge ensemble (majority vote).** Higher cost, slower,
  and adds complexity we don't need at current eval volume (24 scenarios × 2
  archetypes = 48 judge calls per run). Can upgrade in Phase 2D if external
  defensibility requires independent corroboration.

**Chosen: Pattern 3.** Single judge, structured rubric, median-of-3 sampling.

**Phase 2D upgrade path:** If external buyers request independent corroboration,
add a second judge (e.g., Claude Sonnet via eval-judge-sonnet) and report
agreement rate alongside the primary DeepSeek R1 scores.

### Judge model: qwen/qwen3-32b via Groq

**Original intent:** deepseek-r1-distill-llama-70b via Groq.

**Model substitution (2026-05-17):** Groq decommissioned `deepseek-r1-distill-llama-70b`
before the baseline run. Substituted with `qwen/qwen3-32b` (Alibaba Qwen3 32B),
which preserves all key properties of the original design:
- **Reasoning-tuned by design.** Qwen3-32B emits `<think>...</think>` chain-of-thought
  before its final JSON answer. The same `_strip_thinking()` helper handles both
  DeepSeek R1 and Qwen3 output. `max_tokens` raised to 2048 because Qwen3 think
  blocks average ~500 tokens vs ~200 for DeepSeek R1.
- **Cross-family from evaluated models.** Evaluated profiles use Haiku (Anthropic)
  and Llama 3.3 70B (Meta). Qwen3-32B is from Alibaba — a different model family,
  preserving the cross-family bias mitigation.
- **Free on Groq free tier.** Accommodates nightly eval volume
  (24 scenarios × 2 archetypes × 3 samples = 144 calls/run).
- **Low latency.** Groq inference; ~1s per call including think block generation.

**Alternative kept for external defensibility:**  
`eval-judge-sonnet` (Claude Sonnet 4.6, Anthropic) is registered in
`llm_routing.yaml` and selectable via `--judge-profile eval-judge-sonnet` on the
scorer CLI. Not used in CI. Available for manual spot-checks or when presenting
eval results to buyers.

### Bias acknowledgment and mitigations

**Within-family bias:** A judge from family A may systematically rate family A's
outputs higher than family B's outputs. DeepSeek R1 is cross-family from both
evaluated models (Haiku and Llama), reducing but not eliminating this risk.

**Absolute vs relative use:** Coherence scores are used for **relative comparison
and regression detection**, not as absolute quality claims. The CI gate trips when
the average drops below `baseline_avg - 0.5`, not when it drops below any
specific absolute threshold like "4.0." This means the gate is valid even if the
judge has a systematic offset, as long as the offset is stable.

**Rubric V1:** The judge system prompt is version-locked for this phase. Future
prompt iterations (V2+) require a separate PR with before/after eval numbers.

### Variance handling: median-of-3 sampling

Each archetype explanation is scored 3 times with `temperature=0.0`. The median
of the 3 scores is the final score. Three identical calls at temperature=0 don't
guarantee identical outputs (different decoding paths are possible), but the
median suppresses outliers from occasional model instability.

**High-variance flag:** When `max(scores) - min(scores) > 2`, the scenario is
flagged `high_variance=True` in the report. These are candidates for human review.
A run where >20% of archetypes are high-variance is a signal that the judge
prompt or model is unstable — the CI gate in S3 checks this threshold.

### Cache design: persistent JSON, invalidated by explanation change

Judge results are cached in `evals/optimizer/cache/judge_cache.json` keyed by
`sha256(scenario_id + archetype_label + explanation_text)[:32]`. Once cached, a
result is never recomputed unless the explanation changes. This makes re-runs on
unchanged code free in both cost ($0 for Groq) and time.

The cache is not checked into git (`.gitignore`). It is populated during CI runs
and preserved between nightly runs via the existing artifact upload mechanism.

## Consequences

**Positive:**
- Coherence regression detection is automated and costs $0 to run in CI.
- DeepSeek R1's explicit chain-of-thought improves score interpretability
  (the `<think>` block can be logged for debugging, even though it's stripped
  before scoring).
- Cache makes repeated runs on unchanged code instant.

**Negative/risks:**
- Single judge bias is documented but not eliminated. Scores are not suitable
  for absolute quality claims in external publications without the two-judge
  corroboration step (Phase 2D).
- The `judge_cache.json` is a local artifact. If CI starts fresh without a cache,
  all 144 calls are re-made (still within Groq free tier limits).
- Rubric V1 is not validated on a human-rated ground truth. Score calibration
  (what "4" means in absolute terms) is unknown; only relative comparisons are
  meaningful.

## Rubric V1

```
5 = Explanation is logically coherent, references the specific flight's actual
    price/duration/stops, and the "ideal traveler" framing makes sense for that
    flight's tradeoffs.
4 = Coherent and references the flight's specifics, with minor framing weakness.
3 = Generally coherent but generic — could apply to many flights, not specifically
    this one.
2 = Has a logical break or factual mismatch with the flight's actual attributes.
1 = Incoherent, contradictory, or describes a different flight than the one shown.
```

**structural_valid:** True when the explanation references the actual flight's
attributes (price/duration/stops in the same ballpark). False if it mentions
details that clearly don't match the flight.
