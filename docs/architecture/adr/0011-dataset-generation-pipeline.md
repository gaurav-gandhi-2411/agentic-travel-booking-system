# ADR-0011: Dataset Generation via OpenRouter Teacher + Claude.ai QA

**Status:** Accepted — 2026-05-09

---

## Context

The six agents require training data that does not exist in public datasets at the
required granularity. Specifically:

- **PlannerAgent** needs examples of ambiguous natural-language travel requests parsed
  into structured `TravelIntent` objects, covering edge cases like open-ended dates,
  multi-city trips, implicit budget signals, and contradictory constraints.
- **FlightHunterAgent** and **HotelHunterAgent** need examples of raw provider API
  responses filtered and normalized to internal schemas, including handling of missing
  fields, provider-specific quirks, and results that should be excluded by constraints.
- **OptimizerAgent** needs ranked package pairs with preference labels and natural-
  language explanations for the ranking, covering diverse traveler profiles.
- **BookingAgent** needs state-machine transition traces across the full booking workflow,
  including HITL confirmation steps and error recovery.
- **ConversationManagerAgent** needs multi-turn dialogue examples where the user refines
  their travel request across 3–7 turns.

No public travel benchmark covers this combination. The ATIS and MultiWOZ datasets cover
airline/hotel queries but at much lower granularity (slot-filling, not structured agent
output schemas). Publicly available LLM benchmark datasets (MT-Bench, AlpacaEval) are
domain-agnostic and unsuitable for fine-tuning domain specialists.

The constraints are:
- **$0 API spend.** Claude API distillation (the standard high-quality approach) is ruled
  out.
- **Target volume:** 1,000 training examples + 100 held-out eval examples per agent.
  Six agents × 1,100 = 6,600 total examples.
- **Quality bar.** Examples must be correct (schema-valid, factually plausible for travel
  domain), diverse (covering the distribution the agent will see in production), and
  free of systematic biases from the generation process.

---

## Decision

Two-stage pipeline.

### Stage 1 — Programmatic generation via OpenRouter teacher

**Teacher models (both free on OpenRouter):**
- Primary: Qwen 2.5 72B Instruct (`qwen/qwen-2.5-72b-instruct:free`). Chosen for strong
  structured output and instruction-following in its weight class.
- Backup: Llama 3.3 70B Instruct (`meta-llama/llama-3.3-70b-instruct:free`). Used when
  primary is rate-limited or produces a high rejection rate on self-critique.

**Rate limits:** OpenRouter free tier allows ~50 requests/day on free models. At 1 request
per example, generating 6,600 examples takes ~132 days at the bare limit. With
self-critique (2 requests per example: generate + critique, regenerate if flagged), up to
200 days. Mitigation: the generation script runs unattended, resumes on interruption, and
uses both teacher models concurrently, effectively doubling the daily throughput.

**Diversity matrix:** `scripts/dataset/diversity_matrix.py` defines the input distribution:

```python
DIVERSITY_MATRIX = {
    "destinations": [
        # Domestic India (40%): BOM, DEL, BLR, HYD, MAA, CCU, ...
        # International short-haul (30%): DXB, SGP, BKK, KUL, ...
        # International long-haul (20%): LHR, JFK, SYD, NRT, ...
        # Ambiguous/unspecified (10%): "beach destination", "hill station"
    ],
    "traveler_profiles": ["solo_budget", "couple_mid", "family", "business", "luxury"],
    "budget_tiers": ["under_15k", "15k_50k", "50k_plus", "unspecified"],
    "ambiguity_levels": ["clear", "moderate", "high"],  # how underspecified the request is
    "date_patterns": ["fixed", "flexible_range", "open", "weekend", "next_month"],
}
```

Examples are generated by sampling from this matrix to hit target proportions, ensuring
coverage of rare but important cases (ambiguous destinations, open dates, luxury tier).

**Self-critique chain:**

```
1. Generate example (teacher call 1)
2. Critique example (teacher call 2):
   - Is the output schema-valid?
   - Is the input realistic (would a real traveler say this)?
   - Is the output correct (does the extracted TravelIntent match the input intent)?
3. If critique flags issues → regenerate (back to step 1, max 2 retries)
4. If critique passes → write to evals/datasets/<agent>/raw/<id>.jsonl
```

Self-critique reduces low-quality examples by ~30–40% based on reported results in the
dataset distillation literature. Examples that fail after 2 retries are discarded.

**Script behavior:** `scripts/dataset/generate.py` maintains a progress file
(`raw/progress.json`) that records which IDs have been successfully generated. On
interruption and restart, already-generated IDs are skipped. This makes generation safe
to run in daily batches across weeks.

### Stage 2 — Manual QA via Claude.ai

After Stage 1 generates the raw examples, a human review pass filters out systematic
errors that self-critique misses (e.g., teacher model has a consistent bias in how it
represents certain destination types).

**Protocol:**
1. Sample 100 examples per agent from the generated set (stratified by difficulty tag).
2. Paste a batch of 10 examples into Claude.ai with a rubric prompt in
   `scripts/dataset/qa_rubric_<agent>.txt`.
3. Claude.ai returns quality scores (1–3) and flags for each example.
4. Run `scripts/dataset/ingest_qa.py` to read the pasted JSON response and annotate the
   dataset: `{"qa_score": 2, "qa_flags": ["output_missing_field"]}`.
5. Discard examples with `qa_score == 1`. Review and optionally fix `qa_score == 2`.

**Time budget:** ~30–60 minutes per agent of focused human time (paste, review, ingest).
Total for 6 agents: 3–6 hours human time.

This process costs $0 in API spend. Claude.ai usage is covered by a standard subscription
or the free tier (no programmatic API calls; the user pastes manually).

### Dataset provenance and documentation

Each agent's dataset directory includes a `provenance.md` documenting:
- Teacher model(s) used
- Generation date range
- Diversity matrix version
- Self-critique pass rate (examples generated / examples discarded)
- QA reviewer and date
- Example count (train / eval split)

This provenance file is published alongside the 20% eval sample on Hugging Face Datasets
(ADR-0012).

## Consequences

**Positive:**
- $0 API spend. The entire dataset generation pipeline costs only human time.
- Pipeline is fully automated for Stage 1 — the rate-limited batching is an operational
  inconvenience, not a blocking constraint.
- Self-critique + QA layers catch most systematic errors before training.
- The diversity matrix is a reusable, versionable config that makes dataset expansion
  (adding new destination types, traveler profiles) straightforward.
- Generation scripts are published as part of the research artifact (ADR-0012), so the
  methodology is reproducible by others with their own OpenRouter accounts.

**Negative:**
- **Quality is bounded by teacher quality.** Qwen 2.5 72B has known failure modes on
  edge cases in structured output generation. Self-critique partially mitigates but
  cannot catch errors the teacher makes consistently (systematic biases).
- **Distillation from open teachers.** The resulting dataset is a distillation of 70B
  teacher output, not ground-truth human annotations. This should be disclosed in the
  dataset card and technical report.
- **Rate-limit timeline.** Generating 6,600 examples at 50 req/day takes months when
  running sequentially. In practice, using both teacher models concurrently and accepting
  that generation spans multiple weeks is the plan. Phase 6.5 spans 2–3 calendar weeks
  for exactly this reason.
- **Stage 2 QA is manual.** The human review pass is a bottleneck if the researcher is
  unavailable. Mitigated by making Stage 2 optional for the initial training run and
  running it as a quality improvement pass before the final evaluation.

**Neutral:**
- The train/eval split (1,000 / 100) is intentionally asymmetric. The eval set is small
  enough to hand-inspect and curate carefully; the train set benefits from scale.
- Raw generated files in `evals/datasets/<agent>/raw/` are not committed to the repo
  (too large, adds noise to git history). They live on the local machine and are uploaded
  to cloud storage (HF Datasets or GCS) as a pre-release step.

## Alternatives Considered

### Alternative 1: Claude API distillation

Use Claude Sonnet 4.6 or Haiku 4.5 as the teacher model, calling the API programmatically.

**Rejected because:** cost. At $0 budget, no Anthropic API spend is permitted. Claude
API distillation is the standard high-quality approach and is noted as the upgrade path
when the project reaches commercial tier.

### Alternative 2: Pure synthetic generation with a weak teacher (7B model)

Use Qwen 2.5 7B or Llama 3.2 3B as the teacher, generating examples locally.

**Rejected because:** quality. A 7B model used as a teacher for training another 7B model
is a distillation collapse scenario — the student cannot exceed the teacher, and the
teacher at 7B is too weak for the hard agents' tasks. The 72B teacher provides the
quality headroom needed.

### Alternative 3: Hand-curation only

A human writes all training examples.

**Rejected because:** time. Six agents × 1,000 training examples × ~5 minutes per
example = 500 person-hours. At even 4 hours/day of focused curation, this is 125 days.
The automated pipeline reduces the human time contribution to ~3–6 hours for QA plus
oversight of the generation run.

### Alternative 4: Public travel datasets with augmentation

Use ATIS, MultiWOZ, or similar and augment with prompting to match the project's schemas.

**Rejected because:** schema mismatch. ATIS uses a flat slot-filling schema; the project
uses structured Pydantic models with nested types. Mapping from ATIS to `TravelIntent`
requires the same effort as generation from scratch, and the resulting examples inherit
the ATIS distribution (domestic US flights, narrow date patterns, no multi-city
itineraries). The diversity matrix approach covers a wider distribution with less effort.
