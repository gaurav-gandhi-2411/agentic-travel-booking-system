# DealHunter Demo Script — Sunday Client Demo

**Duration:** ~12–15 minutes including Q&A  
**Format:** Live browser, backend running, no slides required  
**Setup:** Have the demo page open at http://localhost:3000/demo (or production URL). Disable notifications. Open DevTools (Network tab, filter: EventStream) but keep minimised until needed.

---

## Pre-flight checklist (15 min before)

- [ ] Backend is running (`uvicorn travel_agent.api.main:app --reload`)
- [ ] Frontend is running (`npm run dev`) or production URL is live
- [ ] Run Query 1 ("Delhi to Dubai in June") once yourself — absorbs cold start
- [ ] Confirm both archetype cards render with "Why this?" button visible
- [ ] Confirm "Make it cheaper" chip appears after results load
- [ ] Confirm "Skip red-eyes" and "Non-stop only" chips also work

## Opening (30 seconds, while client is settling in)

> *"Most travel search asks you to know what you want before you start — exact dates, exact destination, airline preference. DealHunter works differently. You express intent in natural language, and the system figures out the rest."*

Point at the search box.

> *"There's no date picker. No airline dropdown. Just tell it what you want."*

---

## Query 1 — Base capability (3 minutes)

Type: **"Delhi to Dubai in June"**  
Hit search.

**While the progress feed is loading, narrate:**

> *"What's happening behind the scenes: the planner agent is reading the query and extracting a structured intent — origin, destination, a 30-day search window for June. Then the flight hunter is querying across that window in parallel. Finally, the optimizer is running Pareto analysis across all options — two objectives, price and experience — and surfacing exactly two recommendations."*

**When both archetype cards appear:**

> *"Two options. Best Value and Best Experience. Not four hundred results you have to scroll through — two, with the reasoning visible."*

Point to the explanation text on each card.

> *"These aren't canned descriptions. That text is generated by the optimizer agent after seeing the actual flight data — it knows this specific flight's price, stops, and departure time."*

**Click "Why this?" on Best Value:**

> *"And here's the tradeoff made explicit — why you'd pick this over the alternative, in plain English."*

## The Wow Moment — Refinement (3 minutes)

While still on the Singapore results, point to the refinement section below the cards.

> *"Now here's what makes this different from a search engine. You can reason with it."*

Click the **"Make it cheaper"** chip.

> *"The system doesn't go back to the flight API. It re-filters the existing result set in memory and re-runs the optimizer. Watch."*

**Wait for new archetypes (should be under 2 seconds).**

> *"New recommendations. Cheaper options. Same route, no waiting for a new API call."*

Click **"Non-stop only"** chip.

> *"Now non-stop only — again, instant. It's not querying anything, it's reasoning over what it already knows."*

Optional if time allows — type in the free-text box: **"I prefer morning departures"**

> *"And you can express more complex preferences in natural language. The system will parse that and apply it."*

## Showing architectural flexibility — the toggle moment (2 minutes)

After Query 2 results appear (Singapore), point to the toggle in the top-right corner.

> *"One more thing. See this toggle — 'Premium' vs 'Open-source'? Right now we're running on Anthropic Haiku. Same query, different model."*

Click **"Open-source (Llama via Groq)"**.

> *"Llama 3.3 70B via Groq. Open-source. Free tier. Same architecture."*

Click the **"Make it cheaper"** chip (refinement section, still visible).

> *"Same refinement logic. Different model. Results in 3-5 seconds."*

When the new archetypes appear:

> *"Two valid recommendations. Production tenants choose their own provider — cost-sensitive deployments run open-source via Groq or self-hosted vLLM; quality-sensitive deployments use Anthropic or OpenAI. The agent protocol is provider-agnostic."*

Switch back to "Premium" before the next query to return to baseline.

**Talking points when asked about model choice:**
- "The routing is config-driven — you change one YAML value, the entire pipeline switches."
- "For the demo, Haiku is faster and more reliable on complex tool calling. Llama is free and 90% of the quality."
- "In production, tenants supply their own API key. We don't see their data."

## Likely client questions — scripted answers

**"How is this different from Skyscanner?"**
> *"Skyscanner requires exact parameters — date, destination, airline class. We accept ambiguous intent. The difference is decision-time: we give you 2 options with reasoning versus 400 results you have to compare yourself."*

**"Where is the AI? How do I know it's real?"**
> Open DevTools → Network → filter to EventStream. Show the streaming SSE events in real-time.
> *"Every step is visible in the event stream. The planner extracted the intent, the search ran, the optimizer generated those explanations. It's not a static page — you're watching live agent reasoning."*

**"What about hotels?"**
> *"Same architecture, currently scaffolded. The hotel hunter agent exists, the scoring functions exist, the Pareto analysis works across flight+hotel packages. Production: next sprint. We built flight-only first so we could validate the core reasoning loop cleanly."*

**"What's the business model?"**
> *"Two tracks: affiliate revenue on bookings (we already have Aviasales partner integration), and B2B SDK licensing — travel platforms that want to embed agentic reasoning into their product without building the agent infrastructure themselves."*

**"Can it handle group bookings?"**
> *"traveler_count is a field in the intent model. The pricing scales. UI for seat selection is Phase D."*

**"What about flight availability / booking integration?"**
> *"The deeplink goes directly to Aviasales for booking. Full GDS integration (live availability, seat maps, PNR) is Phase D. For the demo we're using Travelpayouts cached pricing data."*

**"Can it handle edge cases like [X]?"**
> Map to roadmap. Don't fabricate. ADR-0001 through ADR-0015 document the design decisions.

## Recovery scripts — if something breaks

**Cold start / slow first query:**
> *"First call always takes a moment as the agent spins up. Subsequent queries are much faster — the models stay warm."*

**Empty results ("No flights found"):**
> *"This route has limited cached data in the demo provider. Let me try a different route."*  
> Switch to: **"Mumbai to Paris in July"** — guaranteed to have synthetic data.

**Optimizer error / generic failure:**
> *"One of the agents hit a timeout — this happens occasionally with the free-tier LLM endpoint. Let me retry."*  
> Hit the retry button. If it fails again, switch to a different query.

**Refinement shows no change:**
> *"The filter applied, but the top options happen to be the same flights — they were already the cheapest non-stop options available. Let me try a different refinement."*  
> Try "Skip red-eyes" instead.

**Frontend doesn't load:**
> Open browser console, show the error. Pivot to architecture walkthrough: open the code in VS Code, walk through the agent pipeline in plain English. The code is readable.

## 3-query walkthrough (for a non-engineer co-presenter)

1. Go to [demo URL], you'll see a text input and a "Premium / Open-source" toggle in the top-right. Leave toggle on **Premium**.
2. Type `Delhi to Dubai in June` and press Enter or click search.
3. Watch the three progress steps: Understanding → Searching → Ranking.
4. Two cards appear. Click "Why this?" on the left (teal) card. Read the comparison text aloud.
5. Scroll down. Click "Make it cheaper". Point out the lower prices when new cards appear (< 2 seconds).
6. Type `Delhi to Singapore in June` in the main search box. Wait for results.
7. **Toggle moment**: click "Open-source (Llama via Groq)" in the top-right. Then click "Make it cheaper". New results appear from a different model. Say: "Same architecture, different provider."
8. Switch back to "Premium". Done.

**Total time: 10–12 minutes at a relaxed pace.**
